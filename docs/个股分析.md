# 个股分析架构与 Skills 说明

## 1. 总体理解

个股分析不是单一模型直接给出结论，而是一个多源分析编排流程。系统先调用基本面、技术面、缠论、因子、风险和情绪等专业分析 Skill，分别产出结构化结果；然后通过统一的 LLM 层进行多空证据归纳和冲突识别；同时通过 RAG 五步法检索公告等非结构化资料，补充可追溯的研究证据；最后将所有结果汇总为个股诊断报告。

```text
行情与财务数据
      ↓
┌─────────────────────────────────────────┐
│ 专业分析 Skills（当前主要是规则分析器） │
│ 基本面｜技术面｜缠论｜因子｜风险｜情绪   │
└─────────────────────────────────────────┘
      ↓
统一结构：观点 + 评分 + 置信度 + 证据 + 反向证据
      ↓
LLM 综合层：多空归纳、冲突识别、最终共识
      ↑
RAG 五步法：检索公告等非结构化资料并生成研究结果
      ↓
综合个股诊断报告
```

> 当前代码中，这些 Skill 并不是六个独立的 LLM 服务，而是读取前置分析结果并转换成统一 Agent 输出的 `rule-adapter`。真正的 LLM 主要用于最终共识分析和 RAG 研究。

## 2. 统一输出结构

六个 Skill 的结果会通过 `run_agents(context, enabled)` 统一转换为以下结构：

```json
{
  "agent_type": "technical",
  "status": "completed",
  "opinion": "bullish",
  "score": 76,
  "confidence": 0.9,
  "summary": "技术趋势：上升。",
  "evidence": [],
  "counter_evidence": [],
  "data_as_of": "2026-09-03",
  "model_name": "rule-adapter",
  "prompt_version": "diagnosis-agent-v1",
  "algorithm_version": "diagnosis-agent-v1",
  "created_at": "2026-09-04T10:30:00"
}
```

| 字段 | 含义 |
|---|---|
| `agent_type` | Skill/分析角色名称，如 `fundamental`、`technical`。 |
| `status` | 执行状态，正常为 `completed`，异常时为 `failed`。 |
| `opinion` | 标准化方向观点：`bullish` 看多、`neutral` 中性、`bearish` 看空。 |
| `score` | Skill 的量化评分。多数评分是 0～100；情绪 Skill 当前使用 -1、0、1 表示方向。 |
| `confidence` | 结果置信度，范围为 0～1，不等同于上涨概率。 |
| `summary` | 面向上层汇总的自然语言摘要。 |
| `evidence` | 支持当前观点的证据列表。 |
| `counter_evidence` | 与当前观点相反的证据或风险证据。 |
| `data_as_of` | 该 Skill 使用的数据截止日期。 |
| `model_name` | 结果生成方式，当前为 `rule-adapter`，表示规则适配器。 |
| `prompt_version` | Agent 输出规范或提示词版本。 |
| `algorithm_version` | 分析算法版本，便于结果追踪和复现。 |
| `created_at` | 结果生成时间。 |

证据统一包含以下字段：

```json
{
  "source": "trade_stock_financial",
  "field": "score",
  "value": 82,
  "data_as_of": "2026-06-30",
  "summary": "基本面综合评分"
}
```

| 证据字段 | 含义 |
|---|---|
| `source` | 数据来源表、分析模块或数据源。 |
| `field` | 被引用的字段名。 |
| `value` | 字段的实际值。 |
| `data_as_of` | 证据对应的数据日期。 |
| `summary` | 对该证据业务含义的说明。 |

## 3. 基本面 Skill（`fundamental`）

### 业务逻辑

基本面 Skill 关注公司的盈利能力、资产质量、偿债能力和现金流质量，主要读取 `trade_stock_financial` 中最近 8 期财务数据。

执行逻辑：

1. 按股票代码查询最近 8 期财务数据。
2. 检查最近 4 期是否至少有足够的财务明细字段。
3. 如果明细不足，则尝试同步最近 4 个季度并补全财务数据。
4. 取最新一期作为当前状态，同时保留历史数据用于趋势观察。
5. 将 `ROE`、`ROA`、毛利率作为当前简化评分依据。
6. 当前代码使用 `50 + mean(ROE, ROA, gross_margin)` 生成基础评分，并限制在 0～100。
7. Agent 层再将评分转换为观点：评分大于等于 70 看多，小于 50 看空，其余中性。

### 原始输出示例

```json
{
  "report_date": "2026-06-30",
  "metrics": {
    "revenue": {"value": 1200000000, "data_date": "2026-06-30", "source": "trade_stock_financial"},
    "net_profit": {"value": 260000000, "data_date": "2026-06-30", "source": "trade_stock_financial"},
    "eps": {"value": 2.6, "data_date": "2026-06-30", "source": "trade_stock_financial"},
    "roe": {"value": 0.30, "data_date": "2026-06-30", "source": "trade_stock_financial"},
    "roa": {"value": 0.12, "data_date": "2026-06-30", "source": "trade_stock_financial"},
    "gross_margin": {"value": 0.48, "data_date": "2026-06-30", "source": "trade_stock_financial"},
    "net_margin": {"value": 0.22, "data_date": "2026-06-30", "source": "trade_stock_financial"},
    "debt_ratio": {"value": 0.35, "data_date": "2026-06-30", "source": "trade_stock_financial"},
    "current_ratio": {"value": 1.8, "data_date": "2026-06-30", "source": "trade_stock_financial"},
    "operating_cashflow": {"value": 310000000, "data_date": "2026-06-30", "source": "trade_stock_financial"}
  },
  "history": [],
  "score": 70,
  "status": "healthy",
  "data_source": "trade_stock_financial",
  "detail_refreshed": false
}
```

### 字段含义

| 字段 | 含义 |
|---|---|
| `report_date` | 最新财务报告期，不是接口调用时间。 |
| `metrics` | 当前最新一期的财务指标及其来源和日期。 |
| `revenue` / `net_profit` | 营业收入 / 净利润，反映公司规模和盈利结果。 |
| `eps` | 每股收益。 |
| `roe` / `roa` | 净资产收益率 / 总资产收益率，反映资本和资产使用效率。 |
| `gross_margin` / `net_margin` | 毛利率 / 净利率，反映产品盈利空间和最终利润质量。 |
| `debt_ratio` / `current_ratio` | 资产负债率 / 流动比率，反映杠杆和短期偿债能力。 |
| `operating_cashflow` | 经营活动现金流，反映利润是否有现金支撑。 |
| `history` | 最近多期原始财务数据，用于纵向比较。 |
| `score` | 当前基本面简化评分。 |
| `status` | `healthy` 表示明细较完整，`partial` 表示数据不完整。 |
| `detail_refreshed` | 本次诊断是否触发了财务明细补全。 |

对应的统一 Agent 输出示例：

```json
{
  "agent_type": "fundamental",
  "status": "completed",
  "opinion": "bullish",
  "score": 70,
  "confidence": 0.8,
  "summary": "基本面指标已完成结构化评估。",
  "evidence": [{"source": "trade_stock_financial", "field": "score", "value": 70, "data_as_of": "2026-06-30", "summary": "基本面综合评分"}],
  "counter_evidence": [{"source": "trade_stock_financial", "field": "history", "value": 8, "data_as_of": "2026-06-30", "summary": "历史财务数据样本量"}],
  "data_as_of": "2026-06-30"
}
```

## 4. 技术面 Skill（`technical`）

### 业务逻辑

技术面 Skill 使用日线行情数据计算趋势、动量、超买超卖和成交量变化：

1. 读取最多 5000 条日线数据。
2. 计算 `MA5`、`MA10`、`MA20`、`MA60`、`MA120`。
3. 计算 14 日 RSI。
4. 计算 MACD：`EMA12 - EMA26` 得到 `DIF`，再计算 `DEA` 和 `MACD`。
5. 计算成交量相对 20 日均量的比例。
6. 如果收盘价大于 `MA20` 且 `MA20 > MA60`，趋势为“上升”。
7. 如果收盘价小于 `MA20`，趋势为“下降”；否则为“震荡”。
8. 取最近 20 日最低价作为支撑位，最近 20 日最高价作为阻力位。

### 原始输出示例

```json
{
  "signal_date": "2026-09-03",
  "metrics": {
    "ma5": 1482.3,
    "ma10": 1468.5,
    "ma20": 1450.2,
    "ma60": 1398.7,
    "ma120": 1350.1,
    "rsi14": 62.4,
    "dif": 18.6,
    "dea": 14.2,
    "macd": 8.8,
    "volume_ratio": 1.25
  },
  "trend": "上升",
  "momentum": "增强",
  "support": 1402.5,
  "resistance": 1510.8,
  "score": 70
}
```

### 字段含义

| 字段 | 含义 |
|---|---|
| `signal_date` | 技术信号对应的交易日。 |
| `ma5` / `ma20` / `ma60` / `ma120` | 不同周期移动平均线，用于判断短、中、长期趋势。 |
| `rsi14` | 14 日相对强弱指标，用于观察强弱和超买超卖。 |
| `dif` / `dea` / `macd` | MACD 的快线、慢线和柱体动量指标。 |
| `volume_ratio` | 当日成交量与 20 日平均成交量的比值。 |
| `trend` | 当前趋势：`上升`、`下降`或`震荡`。 |
| `momentum` | 当前动量状态，代码中根据 MACD 正负简单判断为`增强`或`减弱`。 |
| `support` / `resistance` | 最近 20 日低点 / 高点形成的参考支撑和阻力。 |
| `series` | 最近 120 个交易日的行情和指标序列。 |
| `score` | 当前代码中上升趋势为 70，否则为 40。 |

统一 Agent 输出中，`trend=上升`映射为 `opinion=bullish`，`trend=下降`映射为 `opinion=bearish`。

## 5. 缠论 Skill（`chan`）

### 业务逻辑

缠论 Skill 基于日线的开、高、低、收数据调用 `detect_chan_signals()`：

1. 读取最多 5000 条日线数据。
2. 将交易日设置为索引。
3. 使用 OHLC 数据识别缠论买卖信号。
4. 保留最近 20 个信号。
5. 取最后一个信号作为当前最新信号。
6. 最新信号类型以 `buy` 结尾时评分为 70，否则为 50。
7. Agent 层将以 `buy` 结尾的信号映射为看多，以 `sell` 结尾的信号映射为看空，没有有效信号则中性。

### 原始输出示例

```json
{
  "signal_date": "2026-09-03",
  "signals": [
    {"signal_type": "二买buy", "price": 1440.0, "date": "2026-09-02"}
  ],
  "latest_signal": {"signal_type": "二买buy", "price": 1440.0, "date": "2026-09-02"},
  "message": "已识别有效缠论信号",
  "score": 70
}
```

### 字段含义

| 字段 | 含义 |
|---|---|
| `signal_date` | 当前行情数据的最新交易日。 |
| `signals` | 最近识别出的缠论信号列表。 |
| `latest_signal` | 最近一个缠论信号，作为当前主要参考。 |
| `signal_type` | 买卖信号类型；代码按是否以 `buy` 或 `sell` 结尾进行方向映射。 |
| `price` | 信号对应的价格，具体字段由缠论检测器返回。 |
| `date` | 信号发生日期，具体字段由缠论检测器返回。 |
| `message` | 是否识别到有效信号的可读描述。 |
| `score` | 当前代码中有效买点为 70，其余默认为 50。 |

## 6. 因子 Skill（`factor`）

### 业务逻辑

因子 Skill 当前是一个基于技术数据的简化因子模型，并非完整的多因子量化回测模型：

1. 复用技术面 Skill 的结果。
2. 提取 `MA20` 作为动量代理变量、`RSI14` 作为波动/强弱代理变量、`volume_ratio` 作为流动性代理变量。
3. 初始评分为 60。
4. 技术趋势为“上升”时加 15 分。
5. 动量为“增强”时加 10 分。
6. 最终评分上限为 100。

### 原始输出示例

```json
{
  "factor_version": "diagnosis-v1",
  "factors": {
    "momentum": 1450.2,
    "volatility": 62.4,
    "volume": 1.25
  },
  "categories": {
    "估值": null,
    "成长": null,
    "盈利质量": null,
    "动量": 85,
    "波动率": 62.4,
    "流动性": 1.25
  },
  "score": 85,
  "data_as_of": "2026-09-03"
}
```

### 字段含义

| 字段 | 含义 |
|---|---|
| `factor_version` | 因子模型版本。 |
| `factors.momentum` | 当前代码中使用 `MA20` 作为动量代理值。 |
| `factors.volatility` | 当前代码中使用 RSI14 作为波动/强弱代理值。 |
| `factors.volume` | 成交量相对 20 日均量的比例。 |
| `categories` | 按估值、成长、盈利质量、动量、波动率、流动性分类的因子结果。当前前三类未实现，因此是 `null`。 |
| `score` | 因子综合评分，当前基于趋势和 MACD 动量规则。 |
| `data_as_of` | 因子数据截止日期。 |

Agent 层对因子评分的映射是：评分大于等于 70 看多，小于 50 看空，否则中性。

## 7. 风险 Skill（`risk`）

### 业务逻辑

风险 Skill 综合技术面风险和基本面风险：

1. 如果技术趋势为“下降”，增加高等级 `trend_weak` 风险项。
2. 调用基本面风险计算逻辑，结合财务数据和近期公告生成风险项。
3. 合并所有风险项。
4. 只要存在任意高等级风险，整体风险为 `high`；否则有风险项时为 `medium`；没有风险项时为 `low`。
5. Agent 层将 `high` 映射为看空，`medium` 映射为中性，`low` 映射为偏中性但评分较高。

### 原始输出示例

```json
{
  "level": "high",
  "items": [
    {
      "type": "trend_weak",
      "level": "high",
      "source": "technical",
      "description": "价格位于主要均线下方"
    },
    {
      "type": "debt_ratio_high",
      "level": "medium",
      "source": "fundamental",
      "description": "资产负债率偏高"
    }
  ],
  "fundamental_score": 42,
  "fundamental_level": "medium",
  "fundamental_tags": ["leverage"],
  "fundamental_categories": {"偿债能力": "medium", "盈利质量": "low"},
  "rule_version": "risk-v1"
}
```

### 字段含义

| 字段 | 含义 |
|---|---|
| `level` | 总体风险等级：`high`、`medium`、`low`。 |
| `items` | 具体风险事项列表。 |
| `items.type` | 风险类型编码。 |
| `items.level` | 单个风险项等级。 |
| `items.source` | 风险来源，如 `technical` 或 `fundamental`。 |
| `items.description` | 风险的业务解释。 |
| `fundamental_score` | 基本面风险评分。 |
| `fundamental_level` | 基本面风险等级。 |
| `fundamental_tags` | 风险标签。 |
| `fundamental_categories` | 按风险类别拆分的结果。 |
| `rule_version` | 风险规则版本。 |

## 8. 情绪 Skill（`sentiment`）

### 业务逻辑

情绪 Skill 的原始输入是 `news_policy` 新闻/政策快照，不直接重新抓取新闻：

1. 读取新闻和政策摘要。
2. 读取摘要中的 `direction` 字段。
3. 将 `positive` / `bullish` 映射为看多，将 `negative` / `bearish` 映射为看空，将 `neutral` 映射为中性。
4. 如果方向缺失或无法识别，则默认为中性。
5. 将方向转换为当前统一评分：看多为 1，中性为 0，看空为 -1。
6. 使用新闻快照的 `confidence` 作为情绪结果置信度。
7. 直接复用新闻快照中的证据作为情绪证据。

### 原始输入示例

```json
{
  "summary": {
    "direction": "positive",
    "text": "近期公司公告和行业政策整体偏积极"
  },
  "confidence": 0.75,
  "evidence": [
    {
      "source": "announcement",
      "field": "policy_signal",
      "value": "positive",
      "data_as_of": "2026-09-03",
      "summary": "近期政策信号偏积极"
    }
  ]
}
```

### 统一输出示例

```json
{
  "agent_type": "sentiment",
  "status": "completed",
  "opinion": "bullish",
  "score": 1,
  "confidence": 0.75,
  "summary": "近期公司公告和行业政策整体偏积极",
  "evidence": [
    {
      "source": "announcement",
      "field": "policy_signal",
      "value": "positive",
      "data_as_of": "2026-09-03",
      "summary": "近期政策信号偏积极"
    }
  ],
  "counter_evidence": [],
  "data_as_of": "2026-09-03"
}
```

### 字段含义

| 字段 | 含义 |
|---|---|
| `summary.direction` | 新闻/政策方向，支持 `positive`、`negative`、`bullish`、`bearish`、`neutral`。 |
| `summary.text` | 新闻和政策的自然语言摘要。 |
| `confidence` | 新闻/政策方向判断的置信度。 |
| `evidence` | 支持情绪方向的新闻、公告或政策证据。 |
| `score` | 当前统一层的情绪方向分值：1 看多、0 中性、-1 看空。 |

## 9. Skills 结果如何被 LLM 使用

六个 Skill 执行后形成 `agent_results`：

```text
fundamental ─┐
technical ───┤
chan ────────┤
factor ──────┤→ agent_results → build_llm_consensus() → consensus
risk ────────┤
sentiment ───┘
```

LLM 重点处理：

- 汇总各 Skill 的看多和看空理由；
- 识别不同 Skill 之间的冲突；
- 提取关键证据和风险因素；
- 输出最终 `opinion`、`score`、`confidence` 和摘要；
- 给出结论失效条件。

如果 LLM 调用失败，系统会使用本地规则进行降级：统计多空观点数量，计算有效 Skill 评分平均值，并生成 `local_fallback` 结果。

## 10. 面试表达版本

> 我把个股诊断拆成六个专业分析 Skill：基本面、技术面、缠论、因子、风险和情绪。每个 Skill 负责一个独立分析维度，读取对应的结构化数据或前置计算结果，并统一输出方向观点、评分、置信度、支持证据和反向证据。系统将这些结果汇总后交给 LLM，完成多空证据归纳、冲突识别和最终共识生成；同时通过 RAG 五步法检索公告等非结构化资料，补充可追溯的研究证据，最后形成综合个股诊断报告。

> 需要准确说明的是，当前版本的 Skill 层主要是规则分析器和结果适配器，并非每个 Skill 都独立调用 LLM；LLM 集中在共识分析和 RAG 研究阶段。
